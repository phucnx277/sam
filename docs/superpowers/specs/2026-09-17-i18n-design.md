# i18n (Vietnamese + English) — Design

Date: 2026-09-17
Status: Approved for planning

## Goal

Add internationalization to Sam with Vietnamese (`vi`) and English (`en`) locales.

- Default locale is derived from the browser language setting.
- If the browser language is neither Vietnamese nor English, fall back to Vietnamese.
- The user can switch language at runtime; the choice persists.

The app currently has no i18n layer. UI text is a mix of Vietnamese (game
terms) and English (credentials), scattered across JSX components and the pure
logic layer.

## Decisions

| Decision | Choice |
| --- | --- |
| Language switching | Auto-detect on first load + manual runtime switcher |
| Implementation | Lightweight custom translation layer + Zustand (no new dependency) |
| Fallback locale | Vietnamese |
| Switcher placement | Fixed top-right bar next to `VersionInfo` (Credentials + Tables) and in the `TableInfo` dialog (reachable in-game) |
| Logic-layer coupling | Approach 1: translation keys in logic + framework-free `t()` from `logic/i18n.ts` |
| Persistence | `localStorage` key `sam.locale` (matches existing `sam.*` keys) |
| Verification | `npm run build` (tsc) + `npm run lint` + manual VI/EN pass |

## Architecture

### 1. Dictionaries

- `src/locales/vi.ts` — source of truth for the key set.
  `export const vi = { "action.ready": "Sẵn sàng", ... } as const;`
- `src/locales/en.ts` — must contain every key.
  `export const en = { ... } satisfies Record<TranslationKey, string>;`
  A missing English key is a compile error.

Flat, dotted, namespaced keys. Namespaces:
`action.*`, `hand.*`, `confirm.*`, `error.*`, `credentials.*`, `player.*`,
`table.*`, `lobby.*`, `game.*`, `common.*`.

Interpolation uses `{name}` placeholders, e.g.
`"error.tableFull": "Bàn chỉ chứa tối đa {limit} người"`.

### 2. `src/logic/i18n.ts` (framework-free, no React)

- `export type Locale = "vi" | "en"`
- `export type TranslationKey = keyof typeof vi`
- `export type TParams = Record<string, string | number>`
- `translate(locale, key, params?)`: resolve from the locale dictionary, fall
  back to `vi`, then to the key itself; interpolate `{placeholder}`.
- Module-level current locale with:
  - `setLocale(locale: Locale): void`
  - `getLocale(): Locale`
  - `t(key: TranslationKey, params?: TParams): string` — used by the logic
    layer at runtime.
- `detectLocale(): Locale`: scan `navigator.languages`; prefer the first entry
  starting with `vi`, then `en`, else `"vi"`.
- `LOCALES`: list used by the switcher, e.g.
  `[{ code: "vi", label: "Tiếng Việt" }, { code: "en", label: "English" }]`.

This module stays pure apart from the browser-language read in
`detectLocale()`, which is only invoked by the hook. No React import.

### 3. `src/hooks/useI18n.ts` (Zustand singleton)

- Owns `{ locale, t, setLocale }`.
- `t` is bound to the current locale so components re-render on change.
- Initial locale: valid `sam.locale` from `localStorage`, else `detectLocale()`.
- `setLocale(locale)`:
  1. persist to `sam.locale`,
  2. call `logic.setLocale(locale)` so the logic-layer `t()` matches,
  3. set `document.documentElement.lang`,
  4. update store state (`locale` + rebound `t`).
- At module load, also sync `logic.setLocale` and `<html lang>` so the logic
  layer is correct before the first render.

Components use `const { t } = useI18n();` and translate via `t("some.key")`.
Logic uses `import { t } from "@logic/i18n"`.

### 4. Logic-layer migration

- `ActionDef.label` type becomes `TranslationKey`; values become keys
  (`"action.ready"`, `"action.starOfHope"`, `"action.newGame"`, `"action.deal"`,
  `"action.ask"`, `"action.tiger"`, `"action.play"`, `"action.pass"`,
  `"action.resetSession"`, `"action.removePlayers"`, `"action.transferHost"`).
- `WhiteTigerRankName` in `logic/hand.ts` is replaced by
  `WhiteTigerRankKey: Record<number, TranslationKey>`; `Actions.tsx` translates
  via `t`.
- Runtime confirmations inside `logic/game.ts` use `t(...)`:
  `"confirm.tiger"`, `"confirm.resetSession"`.
- Thrown `Error`s that surface in the UI are localized at throw time with
  `t(key, params)`: `"error.playersExceedLimit"` (`logic/game.ts`),
  `"error.passwordIncorrect"` and `"error.tableFull"` (`logic/table.ts`).
  Internal errors that are never shown (e.g. `useAppData` parse failures) stay
  as-is.

### 5. UI & switcher

- `src/components/common/LanguageSwitcher.tsx`: a native `<select>` wired to
  `useI18n`, showing the full language names from `LOCALES` ("Tiếng Việt" /
  "English") and labelled via the `common.language` key.
- `Credentials.tsx` and `Tables.tsx`: the existing fixed top-right container
  (`<div className="fixed top-2 right-2"><VersionInfo /></div>`) is replaced by
  a shared `src/components/common/TopRightBar.tsx` that renders
  `LanguageSwitcher` and `VersionInfo` together.
- `TableInfo.tsx`: the switcher is rendered in the table-info dialog header
  (next to the copy-link button), so it stays reachable in-game without
  overlaying the play area.
- All hardcoded user-facing literals in components are replaced with `t(...)`:
  `WelcomePlayer`, `InputPlayerInfo`, `InitAppData`, `Tables`, `NewTable`,
  `EnterTable`, `TableInfo`, `PlayingTable`, `PlayerInfo`, `GamePlayer`,
  `VersionInfo`, and every `alert`/`window.confirm`.
- `<html lang>` is set dynamically by the hook. `index.html` `<title>` and PWA
  manifest name `"Sam"` remain unchanged (proper noun).

## Data flow

```
browser language ─┐
                  ├─> detectLocale() ─┐
localStorage ─────┘                   ├─> initial locale ─> useI18n store
                                      │                        │
                                      │                        ├─> <html lang>
                                      │                        └─> logic.setLocale()
                                      └─> (fallback: "vi")         │
                                                                   ▼
   components: t(key) ◄── useI18n.t (bound)      logic: t(key) ◄── module locale
```

## Error handling & edge cases

- Unknown key: fall back to Vietnamese, then return the key itself (safe dev
  behavior).
- Invalid persisted locale value: ignored; re-detect.
- Missing English key: caught at compile time by `satisfies`.
- Interpolation: simple `{name}` replacement; no pluralization needed.
- No `languagechange` listener; the choice is fixed once detected or set.

## Scope / non-goals

- No new dependencies.
- No pluralization/ICU formatting.
- No `@/*` alias usage (fails `tsc` per AGENTS.md); use `@logic`, `@hooks`, or
  relative imports.
- No translation of player names, table names, or other user data.
- Notification/`document.title` translation is out of scope.

## Verification

- `npm run build` — `tsc -b` must pass; this enforces that every
  `TranslationKey` exists in both dictionaries.
- `npm run lint`.
- Manual: load with `vi`, `en`, and an unsupported browser language; confirm
  detection/fallback; switch language on the credentials, tables, table-info,
  and in-game screens and confirm immediate re-render with no reload.
